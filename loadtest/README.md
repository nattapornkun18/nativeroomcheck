# ทดสอบโหลด — 40 คนใช้งานพร้อมกัน

รัน: `node loadtest/run.js`

## นี่คือการจำลอง ไม่ได้ยิงของจริง

ไม่ได้ยิงไปที่ Web App ตัวจริง เพราะจะเขียนแถวขยะลง Google Sheet ที่ใช้งานอยู่จริง
และยิงแจ้งเตือนเข้า LINE หลายร้อยข้อความ — ทดสอบแล้วเก็บกวาดไม่ได้

แทนที่จะเดา ตัวจำลองนับ **จำนวนครั้งที่ `Code.gs` เรียก Sheets API จริง ๆ**
(`cost-model.js` อ้างอิงเลขบรรทัดกำกับไว้ทุกจุด) แล้วคูณด้วยเวลาต่อการเรียกหนึ่งครั้ง
ซึ่งเป็นค่าที่พบได้ทั่วไปใน Apps Script — ไม่ใช่ค่าที่วัดจากชีตของโครงการนี้

เพราะเวลาต่อการเรียกเป็นค่าที่ประมาณเอา จึงรันสามโปรไฟล์ (fast / typical / slow)
ครอบช่วงกว้างกว่า 4 เท่า ถ้าข้อสรุปเหมือนกันทั้งสามโปรไฟล์ แปลว่าไม่ได้ขึ้นกับค่าที่เดา

| ไฟล์ | คืออะไร |
|---|---|
| `cost-model.js` | นับการเรียก Sheets API ต่อหนึ่ง `doPost` / `doGet` ตาม `Code.gs` |
| `sim.js` | จำลองล็อกของ Apps Script + พฤติกรรมส่งซ้ำของหน้าเว็บตาม `index.html` |
| `run.js` | ชุดสถานการณ์ที่รันและพิมพ์ผล |

## สิ่งที่จำลอง

**ฝั่งเซิร์ฟเวอร์** (`Code.gs`)
- `LockService.getScriptLock()` เป็นล็อกเดียวของทั้งสคริปต์ → `doPost` ทุกคนต่อคิวเดียวกัน
- `lock.waitLock(30000)` รอเกิน 30 วิ = ตอบ error กลับไป (`Code.gs:462`)
- `doGet` ไม่ถือล็อก แต่กินสล็อต execution เหมือนกัน
- เพดาน 30 execution พร้อมกัน (Web App รันในนามเจ้าของชีตคนเดียว)

**ฝั่งหน้าเว็บ** (`index.html`)
- `withRetry(..., 3)` ถอยหลัง 1.2 วิ → 2.4 วิ (`index.html:1066`)
- error ของล็อกเข้าเงื่อนไข `/ลองใหม่|กำลังถูกเขียน/` = soft → ลองซ้ำ (`index.html:1059`)
- หมดสามครั้ง → เก็บลง outbox ตั้งเวลาลองใหม่ 4/8/15/30/60 วิ (`index.html:1097`)
- บันทึกสำเร็จ → `pull(true)` ดึงข้อมูลทั้งชุดใหม่หนึ่งรอบ (`index.html:1714`)

## สิ่งที่ไม่ได้จำลอง

- ความเร็วเน็ตของมือถือแต่ละเครื่อง (คิดแค่เวลาฝั่งเซิร์ฟเวอร์)
- โควตาข้อความของ LINE (นับจำนวนข้อความให้ แต่ไม่รู้แพ็กเกจที่ใช้อยู่)
- คนที่เปิดชีตดูเองระหว่างนั้น หรือสั่งเมนู `อัปเดตหน้าสรุป` / `ล้างข้อมูลทั้งห้อง`
  ซึ่งไม่ได้จับล็อกเลย
